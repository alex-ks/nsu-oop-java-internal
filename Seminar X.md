## Unit-тесты. Сухая теория

Unit-тесты - тестируют какую-то маленькую единицу кода - например, конкретный класс. В общем смысле - самостоятельная и неделимая единица кода.

Программу тестируют не для того, чтобы показать отсутствие ошибок, а для того, чтобы находить ошибки. Поэтому тестирование - это процесс деструктивный и по смыслу прямо противоположный разработке. Его цель - не создать, а разрушить.

В тесты нужно включать не только те случаи, которые подходят под понятные сценарии, но и те, которые кажутся бессмысленными по логике вещей, но легальными в плане аргументов программы.

Существуют две стратегии тестирования:
- Чёрный ящик
- Белый ящик

### Стратегия чёрного ящика

Цель - выявить поведение, не соответствующее спецификации (оно же - как можно точнее специфицировать поведение через тест-кейсы).

В чёрном ящике построение исчерпывающего набора тестов, полностью доказывающего корректность программы невозможно - почти всегда множество входных огромно или даже бесконечно.

Поэтому:
- Разбиваем исходные данные на некоторе конечное число классов эквивалентности (ех: массивы чётной длины, массивы нечётной длины) так, чтобы они были показательными (провал теста для одного члена класса скорее всего повлечёт провал и для остальных - зависит от задачи)
- Тестируем различные сценарии для каждого класса
- Определяем граничные значения для каждого класса
  - вроде и в классе, но возможны спецэффекты - например, сортировка массива длины один
  - для интервалом стоит тестировать в прямом смысле границы этих интервалов

### Стратегия белого ящика

Подразумевает исследование внутренней структуры программы. Есть несколько уровней:
1. Каждый оператор программы выполнился хотя бы один раз
2. Каждая ветка программы выполнилась хотя бы раз (true и false для каждого if)
3. Каждый атом условия принимает и true, и false хотя бы один раз (ex: x == 1 && y > 0)
4. Каждая возможная трасса в control-flow графе выполнилась хотя бы один раз (практически невозможно)

Стараемся забраться на уровень повыше и при этом не умереть от старости.
