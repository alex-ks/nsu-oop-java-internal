# Семинар 2020.03.26

## Пятиминутка
- В чём недостаток сборщиков мусора на основе счётчика ссылок?
- Объясните базовый алгоритм Mark-and-Sweep
- Почему нельзя производить Mark-and-Sweep без остановки мира?
- В чём основная идея разбиения объектов на поколения?

*Ответы*
- Такой сборщик мусора не сможет удалить циклически ссылающиеся друг на друга объекты, даже если они больше ниоткуда не достижимы
- Во время сборки мусора программа полностью останавливается; затем, начиная с корневого множества (gc roots) запускается обход объектов: объект помечается (mark), затем обход переходит к тем объектам, на которые ссылается текущий объект, и которые ещё не помечены. Когда обход завершается, все непомеченные объекты удаляются
- Если не остановить мир, то ещё непросмотренная ссылка на объект может поменяться местами с уже просмотренной ссылкой, и потому уже не будет просмотрена - и тогда объект будет удалён, а ссылка - указывать на освобождённую память
- Большинство объектов уничтожаются вскоре после их создания; долгоживущие объекты удаляются редко
